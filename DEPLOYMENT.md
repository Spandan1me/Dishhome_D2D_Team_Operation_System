# Deployment setup

This is a **free-tier prototype setup** for Vercel (frontend), Render (Django API), and Supabase (PostgreSQL and private object storage). It does not publish the app or create cloud resources. Free tiers can sleep, pause, or hit storage/usage limits; this setup is not appropriate for dependable production operations.

## 1. Create a Supabase project

1. Create a Supabase Free project. It includes a PostgreSQL database and limited Storage quota.
2. Create a **private** Storage bucket (for example `visit-evidence`).
3. In the Supabase Storage S3 settings, generate server-side S3 credentials and copy the endpoint and region. Keep the access key and secret private; these credentials can bypass Storage RLS.
4. Copy the Supabase PostgreSQL connection string. Use the Session Pooler connection string if the direct endpoint is unreachable from Render or requires IPv4.

Visit evidence remains private. Django writes to Supabase Storage using its server-only S3 credentials and serves it via the existing authenticated evidence endpoints. Do not put S3 credentials in Vercel or make the bucket public.

## 2. Deploy the Django API to Render

1. Connect the repository to Render and deploy the `render.yaml` Blueprint. It creates a free web service only; the database is hosted by Supabase. Django applies migrations on service startup. It does not seed demo users or data.
2. Set `DATABASE_URL` to the Supabase PostgreSQL connection string and `CORS_ALLOWED_ORIGINS` to the exact Vercel origin (no path or trailing slash).
3. Set the Supabase Storage bucket, S3 endpoint, region, access key, and secret from step 1. The endpoint format is shown in Supabase's Storage S3 settings; copy the dashboard values rather than guessing the region.
4. Confirm `https://dishhome-d2d-api.onrender.com/health/` returns `{"status":"ok"}`. Render Free does not provide shell access. Create the first admin from a trusted local terminal using `python manage.py createsuperuser` while configured with the deployed `DATABASE_URL`, `DJANGO_SETTINGS_MODULE=d2d_project.settings`, and the required production settings; never save those production secrets in the repository. Do not run `seed_demo_data.py`; it creates known demo passwords.

**Free-tier limitations:** Render Free spins the service down after 15 minutes without traffic, so the first request can take about a minute. Its filesystem is ephemeral—do not use it for the database or media. Supabase Free includes 500 MB database and 1 GB file storage and can pause a project after one week of inactivity. Keep a separate backup of important data. Check current provider quotas before use.

Render environment variables:

| Variable | Value |
|---|---|
| `DJANGO_DEBUG` | `False` |
| `DJANGO_SECRET_KEY` | Generated by the Render Blueprint |
| `ALLOWED_HOSTS` | Render hostname and any custom API hostnames |
| `DATABASE_URL` | Supabase PostgreSQL connection string |
| `CORS_ALLOWED_ORIGINS` | Exact Vercel site origin(s), comma-separated |
| `SUPABASE_STORAGE_BUCKET` | Private Storage bucket name |
| `SUPABASE_S3_ENDPOINT` | S3 endpoint from Supabase Storage settings |
| `SUPABASE_S3_REGION` | S3 region from Supabase Storage settings |
| `SUPABASE_S3_ACCESS_KEY_ID` | S3 access key, stored as a Render secret |
| `SUPABASE_S3_SECRET_ACCESS_KEY` | S3 secret key, stored as a Render secret |

## 3. Deploy the frontend to Vercel

1. Import the repository in Vercel and set the project Root Directory to `frontend`.
2. Use Node.js 22.12 or later, `npm run build` as the build command, and `dist` as the output directory.
3. Add `VITE_API_BASE_URL` for Production and Preview, using the corresponding API origin followed by `/api/v1`, for example `https://dishhome-d2d-api.onrender.com/api/v1`.
4. Deploy and verify login, customer allocation, and visit-evidence upload from the HTTPS site. Browser camera access requires HTTPS and user permission.

The SPA rewrite is in `frontend/vercel.json`. The frontend receives only the API URL; database and Supabase S3 credentials stay on Render.

## 4. Local checks and operational notes

- Local development keeps SQLite and local media unless production environment variables are configured.
- The backend accepts uploads up to 60 MB; confirm provider limits before deploying larger videos.
- Production settings refuse to start if the secret key, explicit hosts, PostgreSQL URL, Supabase Storage credentials, or frontend CORS origin are missing.
- Back up PostgreSQL and configure Supabase Storage retention according to your data policy.
- Never commit `.env` files, service-account keys, or production secrets. The root `.gitignore` excludes common local secret and build files.
